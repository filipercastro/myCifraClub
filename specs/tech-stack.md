# Tech Stack

## Delivery

- **Pure static HTML files** — no framework, no bundler, no server required.
- Open directly in a browser via `file://` or serve from any static host (GitHub Pages, Netlify, etc.).

## Structure

```
myCifraClub/
  index.html                    ← song directory / index (generated by generate-index.mjs)
  generate-index.mjs            ← scans songsMD/, emits index.html
  package.json                  ← dev deps (playwright for screenshot tests)
  songs/
    <artist-slug>/
      <song-slug>.html          ← one file per song (generated from songsMD)
  songsMD/
    <Artist Name>/              ← real name, accents preserved
      <Song Title>.md           ← real title, accents preserved (150 files)
  css/
    style.css                   ← shared stylesheet
  specs/                        ← project constitution (this folder)
```

Note: `songsMD/` uses real names (e.g., `Alceu Valença/Anunciação.md`). The `songs/` output uses slugified names derived from them (e.g., `alceu-valenca/anunciacao.html`).

## Content Pipeline

Song `.md` files in `songsMD/` are the canonical source. Each file follows this structure:

```
# Song Title
**Artist Name**

​```
[chord/lyric content]
​```
```

Inside the fenced code block:

- **Chord/lyric pairs** alternate line by line. Chord names are placed at the exact character column above the syllable where each chord falls — preserving this column alignment is what makes the HTML render correctly.
- **Section markers** use the format `== Section Name ==` (e.g., `== Refrão ==`, `== Intro ==`).
- **Column-break marker** `== COLBREAK ==` signals that the song should be rendered in a two-column layout. It marks the approximate midpoint where the content was originally split across columns. All 53 songs sourced from `duas.md` carry this marker; songs from `uma.md` do not.
- Empty lines separate sections.

The `songs/` HTML output slugifies the real artist/song names for use as folder and file names.

## HTML / CSS Conventions

- Semantic HTML5 elements (`<main>`, `<article>`, `<header>`, `<section>`).
- CSS custom properties (variables) for colors, font sizes, and spacing — defined in `:root`.
- Layout via CSS Grid or Flexbox; no external CSS frameworks.
- Font: system-ui stack — no external font loading.
- Chord annotations sit above their lyrics using a two-span pattern inside `.line`. The `.chords` span uses `white-space: pre` to preserve the character-column positioning from the source `.md`:
  ```html
  <div class="line">
    <span class="chords">G                    F9</span>
    <span class="lyrics">Ando devagar porque já tive pressa</span>
  </div>
  ```
- Section labels (`== Refrão ==`, etc.) render as `<p class="marker">`.
- Songs without `== COLBREAK ==` get `<main class="song-body">` — single column, `font-size: 0.65rem`.
- Songs with `== COLBREAK ==` get `<main class="song-body two-col">` — two columns, `columns: 2; column-gap: 2rem`. The marker itself renders as `<p class="marker colbreak">` at the natural split point.

## No JavaScript (initially)

The initial build requires zero JS. JS may be introduced later only for a specific, scoped feature (e.g., transpose, font-size control) and will be self-contained per feature.

## Reference Viewport

**Primary target device: Samsung Galaxy Tab A9+** (11-inch tablet, marketed as "Tab A 11+" in some regions).

- Screen resolution: 1920 × 1200 px
- Browser viewport in landscape (Chrome default): ~1280 × 800 CSS px (150% device pixel ratio)
- Orientation: **portrait** — the fit-to-screen constraint is validated in portrait mode.
- Portrait CSS viewport: ~800 × 1280 CSS px (width and height swapped from landscape).

All layout decisions (font size, column count, padding) must be verified against this viewport in portrait. If content overflows vertically in portrait on this device, the layout is wrong — not the content.
